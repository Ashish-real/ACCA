39.1
Why Excel is the #1 Finance Tool — And Always Will Be

Despite the rise of Python, Power BI, and AI tools, Excel remains the universal language of finance. Every investment banker, Big 4 analyst, CFO, and financial controller uses Excel daily. It is the tool that connects financial theory to real-world practice.

"Excel is the most widely used financial modelling tool in the world. If you want to work in finance, you need to master it — not just know it." — Every Big 4 Partner Ever
💼
How Excel is Used in Finance Roles
  • Investment Banking: DCF models, LBO models, M&A merger models, comparables analysis, pitch books — all built in Excel. Analysts spend 60-80% of their time in Excel.
  • FP&A / Corporate Finance: Annual budgets, rolling forecasts, variance analysis, management reporting — all Excel-based
  • Accounting / Big 4: Trial balance work, audit working papers, reconciliations, financial statement analysis
  • Equity Research: Company models, DCF valuations, ratio analysis, earnings models
  • Risk Management: VaR models, scenario analysis, stress testing, credit models
  • Treasury: Cash flow forecasting, FX position tracking, hedging calculations
  • Tax: Tax computation, deferred tax schedules, transfer pricing analysis
Every Finance Role
📊
Excel Skill Levels — Where Are You?
  • Level 1 — Basic: SUM, AVERAGE, basic charts, simple formatting. Everyone has this. Not enough for finance.
  • Level 2 — Intermediate: VLOOKUP, IF statements, PivotTables, conditional formatting, keyboard shortcuts. Minimum for most finance roles.
  • Level 3 — Advanced: INDEX-MATCH, array formulas, complex nested IFs, dynamic charts, financial functions (NPV/IRR), data tables. Expected at Big 4 / IB analyst level.
  • Level 4 — Expert: Power Query, Power Pivot, VBA/Macros, advanced financial modelling, dynamic arrays (FILTER/SORT/UNIQUE). Differentiates top performers.
  • Goal of this chapter: take you from wherever you are to Level 3-4.
Skill Levels

39.2
Excel Fundamentals — Setup, Navigation & Best Practices
⚙️
Essential Excel Settings to Change First
  • Show Formula Bar: View → Formula Bar → Always ON. See every formula.
  • Show Gridlines: View → Gridlines → ON for working, OFF for presentations
  • Calculation Mode: Formulas → Calculation Options → Automatic (always). Manual only for very large models that slow down.
  • AutoRecover: File → Options → Save → Set to every 5 minutes. Saves you from losing work.
  • Number of Sheets: File → Options → General → Start with 1 sheet (not 3)
  • R1C1 Reference Style: Must be OFF (File → Options → Formulas). Keep A1 style.
  • Quick Access Toolbar: Add your most-used commands — Paste Special, Print Preview, Freeze Panes
Setup First
🏗️
Workbook Structure Best Practices
  • Separate tabs by purpose: Inputs/Assumptions → Calculations → Outputs. Never mix raw data with formulas with outputs.
  • Colour code tabs: Right-click tab → Tab Color. Green = inputs, Blue = calculations, Orange = outputs, Red = instructions
  • Name your sheets clearly: "Revenue Model" not "Sheet1". "Balance Sheet" not "BS".
  • Inputs in one place: All assumptions on one dedicated sheet. Formulas reference this sheet. Change one input → everything updates.
  • Documentation: First tab = Instructions/README — explain what the model does, key assumptions, who built it, when last updated
  • Version control: Save versions — "Model_v1.0_2024-01-15.xlsx". Never overwrite the only copy.
Structure
🎨
Formatting for Finance — The Standard
  • Blue font: Hard-coded inputs (numbers typed directly). Convention: blue = inputs, black = formulas
  • Black font: Formulas (should never type a number directly in a formula cell)
  • Red font / brackets: Negative numbers — standard in finance P&L and cash flow
  • Number formatting: Thousands separator (1,000), 1-2 decimal places, consistent across model
  • Headers: Bold, background colour (dark blue or grey), white font — clear visual hierarchy
  • Borders: Use sparingly — top border for subtotals, double bottom border for totals. Don't over-border.
  • Column widths: Consistent and readable. Don't use merged cells (breaks formula references).
Finance Standard

🔑 The Most Important Shortcut in Finance — Paste Special
Ctrl + Alt + V opens Paste Special — one of the most used shortcuts in finance work.

Paste Values (V then Enter): Paste only the values, not the formula. Essential when you want to "lock in" a number — e.g. paste the result of a calculation as a static number to send to someone without revealing your model.

Paste Multiply/Divide (M or I): Multiply all selected cells by a copied value — e.g. convert all numbers from thousands to millions by copying 1000 and paste-dividing.
39.4
Core Formulas Every Finance Professional Must Know
Mathematical & Statistical Functions
SUM / SUMPRODUCT
=SUM(A1:A10) — adds a range
=SUMPRODUCT(A1:A10,B1:B10) — multiplies arrays and sums. Used for weighted averages, portfolio calculations, WACC.
SUMPRODUCT is one of the most powerful functions in finance — replaces many complex array formulas.
AVERAGE / MEDIAN / MODE
=AVERAGE(A1:A10) — arithmetic mean
=MEDIAN(A1:A10) — middle value (more robust than mean for skewed data)
=MODE(A1:A10) — most frequent value
MIN / MAX / LARGE / SMALL
=MIN(A1:A10) / =MAX(A1:A10) — minimum and maximum
=LARGE(A1:A10,2) — 2nd largest value
=SMALL(A1:A10,3) — 3rd smallest value
ABS / ROUND / ROUNDUP / ROUNDDOWN
=ABS(A1) — absolute value (removes negative sign)
=ROUND(A1,2) — rounds to 2 decimal places
=ROUNDUP(A1,0) — always rounds up (e.g. for ceiling calculations)
=ROUNDDOWN(A1,0) — always rounds down
COUNT / COUNTA / COUNTBLANK
=COUNT(A1:A10) — counts numbers only
=COUNTA(A1:A10) — counts non-empty cells (numbers and text)
=COUNTBLANK(A1:A10) — counts empty cells
Essential for data quality checks — verify expected number of rows/columns.
SUBTOTAL
=SUBTOTAL(9,A1:A100) — SUM that ignores hidden rows (function_num 9=SUM, 1=AVERAGE, 2=COUNT)
Critical when working with filtered data — regular SUM counts hidden rows, SUBTOTAL doesn't. Essential for financial reports with filters.
Absolute vs Relative References — Critical Concept
Relative Reference
=A1 — changes when formula is copied (row and column both move)
Example: =B2*C2 copied down becomes =B3*C3 — references move with the formula. Used for row-by-row calculations.
Absolute Reference
=$A$1 — NEVER changes when copied (locked row AND column)
Press F4 to cycle through reference types. Use for a fixed input (tax rate in cell B2 used across entire model: =$B$2). Critical for financial models — wrong reference type = cascading errors.
Mixed Reference
=$A1 — column locked, row moves | =A$1 — row locked, column moves
Used in data tables and sensitivity analysis. Example: =$A1 in a two-variable data table — column stays on assumption list, row moves across scenarios.
39.5
Lookup Functions — VLOOKUP, INDEX-MATCH, XLOOKUP
Must Master
Lookup Functions — Full Reference
VLOOKUP (Vertical Lookup)
=VLOOKUP(lookup_value, table_array, col_index, [range_lookup])

Example: =VLOOKUP(A2, $D$2:$F$100, 3, FALSE)
→ Find value in A2 in column D of the table, return value from column 3 (column F), exact match (FALSE)

Limitations: Only looks RIGHT (cannot look left). col_index breaks if columns are inserted. Use FALSE for exact match always in finance. Slower than INDEX-MATCH on large datasets.
INDEX-MATCH (The Power Combo)
=INDEX(return_range, MATCH(lookup_value, lookup_range, 0))

Example: =INDEX($F$2:$F$100, MATCH(A2, $D$2:$D$100, 0))
→ MATCH finds the row number where A2 appears in column D. INDEX returns the value from column F at that row.

Advantages over VLOOKUP: Can look LEFT. Does not break when columns inserted. Faster on large data. More flexible. Industry standard in Big 4 and IB models. Always use this instead of VLOOKUP.
XLOOKUP (Modern Replacement)
=XLOOKUP(lookup_value, lookup_array, return_array, [if_not_found], [match_mode], [search_mode])

Example: =XLOOKUP(A2, $D$2:$D$100, $F$2:$F$100, "Not Found")

Available in Excel 365 and Excel 2021+. Combines best of VLOOKUP and INDEX-MATCH. Can look left or right. Built-in error handling (if_not_found). Cleaner syntax. Use XLOOKUP if your Excel version supports it — otherwise use INDEX-MATCH.
MATCH (Standalone)
=MATCH(lookup_value, lookup_array, [match_type])

Example: =MATCH("Revenue", A1:A20, 0) → returns row number of "Revenue" in A1:A20

Returns the POSITION (row or column number) — not the value itself. match_type 0 = exact match. Used inside INDEX-MATCH and for dynamic chart ranges.
OFFSET (Dynamic Ranges)
=OFFSET(reference, rows, cols, [height], [width])

Example: =OFFSET(A1, 5, 2) → cell that is 5 rows down and 2 columns right of A1 (= C6)

Creates dynamic ranges — useful for rolling averages, dynamic chart ranges, expanding datasets. Volatile function (recalculates every time) — use INDEX instead where possible for performance.
💡 INDEX-MATCH vs VLOOKUP — Always Use INDEX-MATCH in Finance
Scenario: You have a client database with Client ID in column A and Revenue in column D. Someone inserts a new column B between A and D — now column D is column E.

VLOOKUP breaks: =VLOOKUP(A2, $A$2:$E$100, 4, FALSE) — was looking for column 4 (D), now column 4 is C (wrong!). Every VLOOKUP in your model is now wrong.

INDEX-MATCH is fine: =INDEX($D$2:$D$100, MATCH(A2, $A$2:$A$100, 0)) — references column D directly. Inserting a column doesn't affect it. The formula still works perfectly.

In a financial model with hundreds of lookups, one inserted column can destroy a VLOOKUP model entirely. This is why professional finance models always use INDEX-MATCH or XLOOKUP.
39.6
Logical & Conditional Functions — IF, IFS, SUMIF, COUNTIF
Logical & Conditional Functions
IF
=IF(logical_test, value_if_true, value_if_false)

Example: =IF(A1>0, "Profit", "Loss")
Finance use: =IF(Revenue>Target, BonusRate*Salary, 0)

Foundation of all conditional logic. Nest IFs for multiple conditions: =IF(A1>100,"High",IF(A1>50,"Medium","Low")) — but nested IFs get complex fast. Use IFS instead.
IFS (Multiple Conditions)
=IFS(condition1, value1, condition2, value2, condition3, value3, ...)

Example: =IFS(Score>=90,"A", Score>=80,"B", Score>=70,"C", TRUE,"F")

Cleaner than nested IFs. Last condition TRUE acts as "else". Available Excel 2019+. In older versions, use nested IF or CHOOSE.
AND / OR / NOT
=AND(condition1, condition2) → TRUE only if ALL conditions true
=OR(condition1, condition2) → TRUE if ANY condition true
=NOT(condition) → reverses TRUE/FALSE

Example: =IF(AND(Revenue>1000, Margin>20%), "Star Product", "Review")
SUMIF / SUMIFS
=SUMIF(range, criteria, sum_range) — sum where ONE condition met
=SUMIFS(sum_range, range1, criteria1, range2, criteria2) — sum where MULTIPLE conditions met

Finance example: =SUMIFS(Revenue, Region, "North", Product, "Software")
→ Sum all revenue where Region="North" AND Product="Software"

Extremely powerful for financial analysis. Used constantly in management reporting, budget vs actual analysis, segment reporting.
COUNTIF / COUNTIFS
=COUNTIF(range, criteria) — count where ONE condition met
=COUNTIFS(range1, criteria1, range2, criteria2) — count where MULTIPLE conditions met

Finance example: =COUNTIFS(Status, "Overdue", Amount, ">"&10000)
→ Count invoices that are overdue AND above ₹10,000
AVERAGEIF / AVERAGEIFS
=AVERAGEIF(range, criteria, average_range)
=AVERAGEIFS(average_range, range1, criteria1, range2, criteria2)

Finance example: =AVERAGEIF(Region, "South", DaysToCollect)
→ Average debtor days for Southern region only
IFERROR / IFNA
=IFERROR(formula, value_if_error) — catch ANY error
=IFNA(formula, value_if_na) — catch only #N/A errors

Example: =IFERROR(VLOOKUP(A1,Table,2,FALSE), "Not Found")
Essential in financial models — prevents ugly #REF!, #N/A, #DIV/0! errors from showing. But be careful: IFERROR can hide genuine formula errors. Only use when errors are expected (e.g. no match found).
39.7
Date & Text Functions — Essential for Data Cleaning
Date Functions
TODAY / NOW
=TODAY() — current date (updates every day)
=NOW() — current date and time
Use TODAY() in dashboard headers, age calculations. WARNING: volatile — recalculates on every change. Freeze with Ctrl+; if you want static date.
DATE / YEAR / MONTH / DAY
=DATE(2025,12,31) — create a date from year/month/day
=YEAR(A1) / =MONTH(A1) / =DAY(A1) — extract components
=DATE(YEAR(A1),MONTH(A1)+1,0) — last day of current month (very useful for financial period end dates)
DATEDIF / DAYS / NETWORKDAYS
=DATEDIF(start_date, end_date, "Y") — years between dates ("M"=months, "D"=days)
=DAYS(end_date, start_date) — number of days between dates
=NETWORKDAYS(start, end, [holidays]) — working days excluding weekends and holidays
NETWORKDAYS critical for payment terms, project deadlines, days outstanding calculations.
EOMONTH
=EOMONTH(start_date, months) — last day of month, n months away
=EOMONTH(A1, 0) — last day of same month as A1
=EOMONTH(A1, 1) — last day of next month
Invaluable for financial model date structures — building monthly/quarterly timelines automatically.
Text Functions — Data Cleaning Essentials
LEFT / RIGHT / MID
=LEFT(A1, 3) — first 3 characters from left
=RIGHT(A1, 4) — last 4 characters from right
=MID(A1, 5, 3) — 3 characters starting from position 5
Used for extracting codes, cleaning IDs, parsing structured text fields.
TRIM / CLEAN / UPPER / LOWER / PROPER
=TRIM(A1) — removes extra spaces (CRITICAL for data cleaning — trailing spaces break lookups)
=CLEAN(A1) — removes non-printable characters
=UPPER/LOWER/PROPER(A1) — change case
Always TRIM data imported from external systems before using VLOOKUP/INDEX-MATCH — most lookup failures are caused by hidden spaces.
CONCATENATE / CONCAT / TEXTJOIN / &
="Hello"&" "&"World" — join text with & operator (simplest)
=CONCAT(A1:A10) — join a range of cells
=TEXTJOIN(", ", TRUE, A1:A10) — join with delimiter, ignoring blanks
Create unique keys by combining fields: =A1&"_"&B1&"_"&C1. Essential for creating match keys in lookups.
FIND / SEARCH / LEN / SUBSTITUTE / REPLACE
=FIND("@",A1) — position of "@" in text (case-sensitive)
=SEARCH("@",A1) — same but case-insensitive
=LEN(A1) — number of characters
=SUBSTITUTE(A1,"old","new") — replace text
=REPLACE(A1,3,2,"XX") — replace characters at position
Used together for complex text parsing: =LEFT(A1,FIND("@",A1)-1) extracts username from email address.
TEXT / VALUE
=TEXT(A1,"#,##0") — format number as text with formatting
=TEXT(A1,"DD-MMM-YYYY") — format date as text
=VALUE(A1) — convert text-number to actual number
Use TEXT to create formatted labels in charts/reports. Use VALUE to fix numbers stored as text (common data import problem).
39.8
Financial Functions — NPV, IRR, PMT, FV, PV
Core for Finance Professionals
Financial Functions — Full Reference with Finance Context
NPV (Net Present Value)
=NPV(rate, value1, value2, ...) + initial_investment

CRITICAL: Excel's NPV assumes cash flows start at END of period 1 (not period 0). Always add period 0 investment separately.

Example: Initial investment ₹100Cr (now), cash flows ₹30Cr, ₹40Cr, ₹50Cr, ₹60Cr, discount rate 12%:
=NPV(12%, 30, 40, 50, 60) + (-100) → correct NPV
NOT: =NPV(12%, -100, 30, 40, 50, 60) → WRONG — this discounts the initial investment which should not be discounted.

If NPV > 0 → Accept project. If NPV < 0 → Reject. Links directly to Chapter 22 (Corporate Finance) and Chapter 33 (Valuation).
XNPV (NPV with Actual Dates)
=XNPV(rate, values, dates)

Example: =XNPV(12%, B2:B6, A2:A6) where A2:A6 are actual dates and B2:B6 are cash flows

More accurate than NPV when cash flows don't occur at exactly equal intervals. Use XNPV in real financial models — NPV assumes equal periods.
IRR (Internal Rate of Return)
=IRR(values, [guess])

Example: =IRR({-100, 30, 40, 50, 60}) → rate at which NPV = 0

Initial investment must be NEGATIVE. Values must include at least one negative (outflow) and one positive (inflow). If IRR > cost of capital (hurdle rate) → Accept. Multiple IRRs possible if cash flows change sign more than once — be careful.
XIRR (IRR with Actual Dates)
=XIRR(values, dates, [guess])

Example: =XIRR(B2:B6, A2:A6) — IRR using actual payment dates

Use XIRR instead of IRR in real models — more accurate when cash flows don't occur at exactly annual intervals. Standard in PE/VC investment returns modelling.
PV (Present Value)
=PV(rate, nper, pmt, [fv], [type])

Example: PV of ₹10,000 received annually for 5 years at 10%:
=PV(10%, 5, -10000) → ₹37,908

rate = periodic rate. nper = number of periods. pmt = periodic payment (negative = outflow). fv = future value. type = 0 (end of period, default) or 1 (beginning of period).
FV (Future Value)
=FV(rate, nper, pmt, [pv], [type])

Example: FV of ₹10,000 invested annually for 10 years at 8%:
=FV(8%, 10, -10000) → ₹1,44,866

FV of lump sum: =FV(8%, 10, 0, -100000) → FV of ₹1L invested today for 10 years at 8%. Useful for retirement planning, savings projections.
PMT (Loan Payment)
=PMT(rate, nper, pv, [fv], [type])

Example: Monthly EMI for ₹50L home loan at 8.5% for 20 years:
=PMT(8.5%/12, 20*12, -5000000) → ₹43,391 per month

rate must match period — for monthly payments, divide annual rate by 12. nper = total number of payments (years × 12 for monthly). Used for loan amortisation schedules, lease payment calculations.
RATE / NPER
=RATE(nper, pmt, pv) — find the interest rate given payments
=NPER(rate, pmt, pv) — find number of periods to repay a loan

Example: =RATE(60, -5000, 200000) → monthly rate on loan of ₹2L, 60 monthly payments of ₹5,000
=NPER(8%/12, -10000, 500000) → months to repay ₹5L at 8% with ₹10,000/month payments
39.9
PivotTables — The Most Powerful Data Analysis Tool
Non-Negotiable Skill

PivotTables are arguably the most powerful feature in Excel for a finance professional. They allow you to instantly summarise, group, filter, and analyse thousands of rows of data in seconds — without writing a single formula.

STEP 01
Prepare Your Data — The Foundation
PivotTables work best with well-structured data: one row per record, no merged cells, no blank rows or columns, clear column headers in row 1, consistent data types in each column (all dates as dates, all numbers as numbers). Pro tip: Convert your data to an Excel Table first (Ctrl+T) — PivotTable will automatically expand as new data is added.
STEP 02
Insert PivotTable — Alt + N + V
Click anywhere in your data range → Insert → PivotTable (or Alt+N+V). Choose where to place it (new sheet recommended). The PivotTable Field List appears on the right — this is where you build your analysis by dragging fields into four areas: Filters (top-level filter), Columns (column headers), Rows (row labels), Values (numbers to aggregate).
STEP 03
Build Your Analysis by Dragging Fields
Typical finance PivotTable: Rows = Product/Region/Cost Centre. Columns = Month/Quarter/Year. Values = Revenue, Cost, Profit (SUM). Filters = Business Unit, Geography. Within Values, right-click → Value Field Settings → choose SUM, COUNT, AVERAGE, MAX, MIN, or % of total. Add multiple values to compare Revenue vs Budget vs Variance in one table.
STEP 04
Group Data — Dates, Numbers, Text
Right-click on a date field in rows/columns → Group → select Days, Months, Quarters, Years. This instantly creates monthly/quarterly/annual summaries from daily transaction data — one of the most powerful features. Also group numbers (e.g. group deal sizes: 0-10Cr, 10-50Cr, 50Cr+). Group text by creating calculated groups.
STEP 05
Calculated Fields & Items
PivotTable Analyze → Fields, Items & Sets → Calculated Field. Add custom calculations within the PivotTable. Example: Calculated Field "Gross Margin%" = Revenue / Profit (where Revenue and Profit are fields in your data). Result: PivotTable automatically shows margin % for every row/column combination — without any formulas outside the PivotTable.
STEP 06
Slicers & Timelines — Interactive Dashboards
PivotTable Analyze → Insert Slicer → select dimensions to filter. Creates interactive buttons — click Region button to filter entire PivotTable. Insert Timeline for date fields — drag slider to select time period. Multiple PivotTables and charts can be connected to the same slicer — one click filters everything. This is how professional Excel dashboards are built.
💡 PivotTable vs Formulas — When to Use Each
Use PivotTables when: You need to explore and summarise large datasets quickly. You don't know the exact analysis you want yet. The data structure may change. You want interactive filters and slicers for a dashboard. You need to group dates into months/quarters automatically.

Use formulas (SUMIFS, INDEX-MATCH) when: The layout and analysis is fixed and defined. You need the output to update automatically with other formula-driven calculations. You want the output in a specific location within a larger model. You need more complex conditional logic than PivotTables support natively.
39.10
Charts & Data Visualisation in Excel
📊
Choosing the Right Chart Type
  • Line Chart: Trends over time — revenue growth, stock price, monthly sales. Best for continuous data over time periods.
  • Bar/Column Chart: Comparison between categories — Q1 vs Q2 vs Q3, North vs South vs East vs West. Column = vertical, Bar = horizontal.
  • Stacked Bar/Column: Show composition AND comparison — revenue by product AND total revenue trend.
  • Pie/Donut Chart: Part of whole — product mix as % of revenue. Use only when parts add to 100% and you have <6 categories. Often overused.
  • Scatter Plot: Relationship between two variables — cost vs revenue, risk vs return. Used in financial analysis for correlation.
  • Waterfall Chart: Bridge from one value to another — shows components of change. Essential for variance analysis (budget vs actual bridge).
  • Combo Chart: Two chart types overlaid — revenue bars + margin line on secondary axis. Very common in financial dashboards.
Chart Selection
✨
Chart Formatting Best Practices
  • Remove chart borders and gridlines: Cleaner look. Keep only horizontal gridlines if needed.
  • Consistent colour palette: Use your company's brand colours. Maximum 4-5 colours per chart. Never use Excel's default colour scheme in professional work.
  • Label directly on chart: Data labels on bars/lines instead of a separate legend where possible — viewer's eye doesn't need to look back and forth.
  • Title is a headline: "Revenue grew 23% YoY in Q3" — not just "Revenue by Quarter". Tell the story in the title.
  • Remove chartjunk: No 3D effects, no shadows, no gradients. Simplicity is professionalism.
  • Source and date: Always add "Source: Company Financials | As of March 2025" at the bottom of important charts.
Design Principles
39.11
Data Validation, Conditional Formatting & Named Ranges
✅
Data Validation — Control Inputs
  • Data → Data Validation → restrict what users can enter in a cell
  • Dropdown list: Create a list of valid options — user selects from dropdown. Example: product categories, department names, yes/no, currency
  • Number validation: Only allow numbers between 0 and 100, or dates within a range
  • Custom formula validation: =AND(A1>0, A1<=100) — only allow values between 0 and 100
  • Input message: Instructions appear when user clicks the cell
  • Error alert: Custom error message if invalid data entered
  • Use in financial models to prevent invalid inputs from breaking calculations. Use in shared files to guide non-finance users.
Input Control
🎨
Conditional Formatting — Visual Flags
  • Automatically format cells based on their values — highlight what matters without manual checking
  • Highlight rules: Cells greater/less than threshold (highlight overdue invoices >30 days in red)
  • Colour scales: Green-yellow-red gradient based on value — heat map for a data table
  • Data bars: Mini bar chart inside the cell — instant visual comparison
  • Icon sets: Traffic light icons, arrows — RAG (Red/Amber/Green) status
  • Formula-based: =AND(A1<Budget, A1<0) — complex custom conditions
  • Finance uses: highlight negative variances in red, cells above/below budget, overdue payments, KPI status in dashboards
Visual Signals
🏷️
Named Ranges — Make Models Readable
  • Assign a name to a cell or range — use the name in formulas instead of cell references
  • Create: select cell → Name Box (top left, shows A1) → type name → Enter
  • Or: Formulas → Define Name → Name Manager for all names
  • Example: Name cell B2 as "TaxRate". Formula: =Revenue*TaxRate instead of =Revenue*$B$2
  • Benefits: Formula reads like English ("=Revenue*TaxRate" vs "=B15*$B$2"). No need to remember cell addresses. Easy to update — change TaxRate cell location without updating every formula.
  • Used extensively in financial models for key assumptions (WACC, Growth Rate, Tax Rate)
  • Dynamic named ranges: =OFFSET(Sheet1!$A$1,0,0,COUNTA(Sheet1!$A:$A)) — expands automatically

What-If Analysis — Goal Seek, Scenario Manager & Data Tables
Essential for Financial Modelling

What-If Analysis tools allow you to explore how changes in inputs affect outputs — essential for sensitivity analysis in valuations, budgets, and business cases.

🎯
Goal Seek — Work Backwards
  • Data → What-If Analysis → Goal Seek
  • Set a specific OUTPUT to a target value by changing one INPUT
  • Finance uses:
  • "What revenue growth rate is needed to achieve ₹100Cr EBITDA?" → Set EBITDA cell = 100, change Revenue Growth Rate cell
  • "What margin do we need to break even?" → Set Profit cell = 0, change Margin % cell
  • "What is the maximum price we can pay for this acquisition and still get 20% IRR?" → Set IRR cell = 20%, change Acquisition Price cell
  • Simple, fast, one-variable. For multiple variables, use Solver (an add-in).
One Variable
📋
Scenario Manager — Multiple Cases
  • Data → What-If Analysis → Scenario Manager
  • Create named scenarios (Base, Bull, Bear) with different sets of input values
  • Switch between scenarios with one click — entire model updates
  • Create a Scenario Summary — table showing all scenarios and key outputs side by side
  • Finance use: Model Bull/Base/Bear cases for a business plan or investment — present all three scenarios in a summary table for the board
  • Limitation: No more than 32 changing cells per scenario. Use separate model tabs for very complex scenarios.
Multiple Cases
📊
Data Tables — Sensitivity Analysis
  • Data → What-If Analysis → Data Table
  • One-variable data table: Shows how one output changes across a range of one input (e.g. how does NPV change as discount rate changes from 8% to 16%?)
  • Two-variable data table: Shows how one output changes across two inputs (e.g. how does equity value change across different WACC × terminal growth rate combinations) — this is the sensitivity matrix from Chapter 33!
  • Automatically calculates all combinations — no need to manually change inputs and record results
  • ACCA AFM: the two-variable data table is exactly the sensitivity table you need to build in exam models
  • Creates a read-only array — cannot edit individual cells in the table

Financial Modelling in Excel — Best Practices & Structure
Professional Standard

Financial modelling is the art of building a numerical representation of a financial situation in Excel. Good models are not just accurate — they are clear, auditable, flexible, and robust. Bad models have caused billion-dollar errors (the "London Whale" JP Morgan loss was partly attributed to a spreadsheet error).

PRINCIPLE 1
Separate Inputs, Calculations, and Outputs
The golden rule of financial modelling. Inputs (assumptions) go on a dedicated sheet — colour coded blue. Calculations go on working sheets — formulas only, never hard-coded numbers. Outputs (P&L, balance sheet, dashboards) pull from calculation sheets. If an input changes, only one cell needs updating — the entire model cascades correctly. Never hard-code a number inside a formula: write =Revenue*Tax_Rate not =Revenue*0.25.
PRINCIPLE 2
One Formula Per Row — Then Copy Across
In a time-series model (monthly/quarterly/annual), write the formula for the first period correctly, then copy it across all remaining periods. Every cell in the same row should have the same formula structure — only the time reference should change. If a formula in the middle of a row looks different, investigate — it usually means an error was "fixed" by typing a number directly.
PRINCIPLE 3
No Circular References
A circular reference is when a formula refers back to itself — directly or indirectly. They cause Excel to use iterative calculations that are unreliable and cause inconsistent results. A classic finance circular: interest on debt → affects net income → affects retained earnings → affects equity → affects leverage → affects interest rate → affects interest on debt. Solution: use a "toggle" approach or calculate interest based on beginning of period debt to break the circle. If Excel says circular reference — fix it, don't enable iterative calculations.
PRINCIPLE 4
Build Checks and Error Flags
Every financial model should have a checks dashboard: Balance sheet balances (Assets = Liabilities + Equity), Cash flow statement reconciles to change in cash on balance sheet, Sum of segments equals total, No #REF!, #N/A, #VALUE! errors anywhere. Use conditional formatting to make these checks glow red if they fail. Professional modellers build a "0/1 toggle" check — if any check fails, a large red "ERROR" appears on the cover page. Never send a model without passing all checks.
PRINCIPLE 5
Document Everything
Add a Notes/Assumptions sheet — document every key assumption, its source, and the date. Add cell comments (Shift+F2) to complex formulas explaining what they calculate. Include a version log — who changed what and when. The model must be understandable to someone who didn't build it. In Big 4 and IB, models are handed between analysts — undocumented models cause errors and wasted time.
PRINCIPLE 6
Stress Test and Sanity Check
Before sharing any model: change key inputs to extreme values and check the model still produces logical results. Set growth rate to 0% — does the model still work? Set costs to zero — does profit equal revenue? Set everything to prior year actuals — does the model reproduce last year's results? Sense-check outputs: does the revenue figure seem reasonable for this type of business? Is the margin in line with the industry? Would a smart person with no finance background find this result believable?

📋 COVER

⚙️ INPUTS
All assumptions, blue font, no formulas — Growth rate, Margins, WACC, Tax rate

Power Query & Power Pivot — Next Level Data
🔄
Power Query — Automate Data Cleaning
  • Data → Get & Transform Data → Power Query. Connect to virtually any data source: Excel files, CSV, databases, web, SharePoint, SharePoint lists, APIs.
  • What Power Query does: Cleans and transforms messy data automatically — remove duplicates, unpivot tables, split columns, merge queries, change data types, filter rows, group and aggregate
  • The game changer: Every transformation step is recorded. When new data arrives, click "Refresh" — all transformations reapply automatically in seconds. What used to take 2 hours of manual Excel work now takes 5 seconds.
  • Finance use cases: Monthly P&L consolidation (merge multiple entity files automatically), Trial balance import and mapping, Bank statement cleaning, ERP data extraction and transformation, GST reconciliation automation
  • M language: Power Query's underlying language — can write custom M code for advanced transformations. Not required for most use cases but good to know exists.
Data Automation
🔗
Power Pivot — Handle Millions of Rows
  • Excel's in-memory data model — handles tens of millions of rows that would crash a regular Excel sheet
  • Create relationships between multiple tables — like a database. Join transaction data with a product master, customer master, and cost centre master all in one model.
  • DAX (Data Analysis Expressions): Formula language for Power Pivot — more powerful than Excel formulas for complex aggregations. CALCULATE, SUMX, RELATED, ALL, FILTER are key functions.
  • Finance use cases: Multi-entity financial consolidation, Large general ledger analysis, Sales analytics across millions of transactions, Combining multiple data sources into one analytical model
  • Foundation of Power BI — learning Power Pivot makes transitioning to Power BI (Chapter 40) much easier

VBA & Macros — Automation Basics

VBA (Visual Basic for Applications) allows you to automate repetitive Excel tasks by writing code. You don't need to be a programmer — even basic VBA knowledge can save hours of manual work every week.

⚡
Macro Recorder — Start Here
  • Developer tab → Record Macro → perform steps → Stop Recording. Excel records every action as VBA code.
  • Play back the macro to repeat all those steps instantly — no matter how many times
  • Finance uses: Format a report (apply styles, freeze panes, print settings) with one click. Export data to a template monthly. Send files to specific folders. Run a monthly close checklist automatically.
  • After recording, open VBA Editor (Alt+F11) and edit the code to make it smarter — add loops, conditions, input prompts
  • Assign macros to buttons on the sheet for non-technical users — click "Generate Report" button → everything runs
Start Here
💻
Key VBA Concepts for Finance
  • Sub and Function: Sub = macro (does something). Function = returns a value (like a custom formula).
  • Variables: Dim x As Long / As String / As Double — store values temporarily
  • Loops (For/For Each): For i = 1 To 100: Next i — repeat an action 100 times. For Each ws In Worksheets — loop through all sheets.
  • If/Then/Else: Conditional logic — If cells value > 0 Then format green Else format red
  • Range and Cells: Range("A1").Value = "Hello" — write to cell. Cells(1,1).Value — same as A1 (useful in loops)
  • With statement: With Range("A1:D10"): .Font.Bold = True: .Interior.Color = vbBlue: End With — apply multiple properties efficiently
  • Error handling: On Error Resume Next — prevent macro from crashing on errors
Core Concepts
💡 When to Use VBA vs Power Query vs Formula
Use Formulas when: The logic is static and the output needs to update live as data changes. Someone else needs to audit or understand the calculation.

Use Power Query when: You need to clean, transform, and load data from external sources on a repeatable basis. Refreshing with new data should be one click.

Use VBA when: You need to automate complex multi-step processes that involve user interaction, file system operations, sending emails, or actions that Power Query and formulas cannot do. Also for custom functions that Excel doesn't have natively.

The modern approach: Power Query for data transformation + DAX/Formulas for calculation + VBA for automation workflows. Together they make a near-unbeatable analytics stack within Excel.

Part B — Most Common Excel Mistakes in Finance

❌ MISTAKE 1
Hard-Coding Numbers Inside Formulas
Writing =Revenue*0.25 instead of =Revenue*TaxRate (where TaxRate is a named cell). When the tax rate changes, you must find and change every formula. Instead: all assumptions in one input sheet, all formulas reference those inputs. Change one cell, everything updates. This is the #1 financial modelling mistake.
❌ MISTAKE 2
Using VLOOKUP Instead of INDEX-MATCH
VLOOKUP breaks when columns are inserted between the lookup column and return column. In a live financial model used by multiple people, columns get inserted constantly. Always use INDEX-MATCH (or XLOOKUP if available) for robust, production-quality models.
❌ MISTAKE 3
Wrong NPV Formula — Including Period 0 in NPV Function
=NPV(rate, -100, 30, 40, 50, 60) discounts the initial investment — which is WRONG. The initial investment is at time 0 and should NOT be discounted. Correct: =NPV(rate, 30, 40, 50, 60) + (-100). This mistake causes systematic undervaluation in every DCF model it appears in.
❌ MISTAKE 4
Not Using Absolute References for Fixed Inputs
Copying a formula that references a tax rate cell without locking it ($B$2 vs B2) means each copied formula references a different cell — usually returning wrong values or errors. Press F4 after clicking a cell reference to lock it. This is the source of more financial model errors than any other single mistake.
❌ MISTAKE 5
Not Building Balance Checks
Sending a model where the balance sheet doesn't balance, or the cash flow statement doesn't reconcile to the balance sheet movement in cash. Always build explicit checks: =IF(Assets=Liabilities+Equity,"✅ Balanced","❌ ERROR"). These checks should be visible on the cover page — and must all be green before sharing.
❌ MISTAKE 6
PMT Rate Not Matching Period
=PMT(8%, 10*12, -500000) — using annual rate for monthly payments. The rate must match the period. For monthly payments: rate = annual rate ÷ 12. For quarterly: rate = annual rate ÷ 4. This mistake produces completely wrong loan/lease calculations.
