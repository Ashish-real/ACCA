40.1
What is Power BI & Why Finance Professionals Need It

Power BI is Microsoft's business intelligence and data visualisation platform. It connects to virtually any data source, transforms and models data, and creates interactive dashboards and reports that update automatically. It is the fastest growing BI tool in the world — and finance is one of its biggest use cases.

"In the old world, you produced a monthly PDF report. In the new world, you build a live dashboard that answers any question instantly. Power BI is what makes that possible." — Every modern CFO
💼
Why Finance Needs Power BI Now
  • Speed: Build a dashboard in hours that would take days in Excel. Refresh with new data in one click.
  • Scale: Handle millions of rows effortlessly — Excel struggles above ~1M rows. Power BI handles 100M+ rows.
  • Interactivity: Users can slice, filter, drill down — answer their own questions without asking the finance team every time
  • Real-time updates: Connect to live databases, ERP systems, cloud sources — dashboard updates automatically
  • Sharing: Publish to Power BI Service — anyone with a browser can view without needing Excel or special software
  • Professional presentation: Pixel-perfect dashboards that look like products, not spreadsheets — impresses senior management
  • Career value: Power BI skill is one of the most demanded in finance job postings in 2025 — significant salary premium
Why Learn It
📊
What Power BI Can Do That Excel Cannot
  • Live connections: Connect directly to databases (SQL, Azure, SAP) — data updates in real time without manual refresh
  • Cross-report filtering: One slicer filters multiple reports and pages simultaneously — impossible in Excel without VBA
  • Mobile optimised: Dashboards automatically reformat for phones — finance teams access KPIs anywhere
  • Row-level security: Different users see different data based on their role — regional managers see only their region
  • Natural language Q&A: Type "show me revenue by region last quarter" in plain English — Power BI generates the visual automatically
  • AI visuals: Key influencers, decomposition tree, anomaly detection — built-in AI analytics
  • Collaboration: Multiple people work on same report simultaneously — impossible with Excel files
Power BI Advantages
🏢
Who Uses Power BI in Finance
  • CFO / Finance Director: Executive KPI dashboard — P&L, cash flow, key ratios at a glance. Updated daily/weekly automatically.
  • FP&A Analyst: Budget vs actual variance reporting, rolling forecasts, scenario comparison — all in one interactive report
  • Management Accountant: Monthly management accounts package — replace static PDF with interactive Power BI report
  • Treasury: Cash position dashboard, FX exposure tracker, liquidity metrics
  • Internal Audit: Continuous audit monitoring dashboards — flag exceptions in real time
  • Tax: GST return analysis, TDS monitoring, transfer pricing analytics
  • Big 4 / Advisory: Client analytics, audit data analysis, risk dashboards delivered as Power BI reports
Finance Use Cases

40.3
The Power BI Workflow — From Data to Dashboard
The Complete Process
STEP 01
Connect to Data Sources
Home → Get Data → choose your source. Power BI connects to 100+ data sources: Excel files, CSV, SQL databases (SQL Server, MySQL, PostgreSQL), cloud databases (Azure SQL, Snowflake, BigQuery), ERP systems (SAP, Oracle, Dynamics 365), web pages, SharePoint lists, APIs, and more. You can connect to multiple sources in the same report — Power BI joins them in the data model. For finance: connect to your ERP for actuals, Excel for budget, and SQL for transactions — all in one report.
STEP 02
Transform Data in Power Query
After connecting, Power Query Editor opens. Here you clean and shape your data: remove unwanted columns, rename columns, change data types (text to number, text to date), filter rows, unpivot tables (column headers become row values — essential for financial data), merge queries (like SQL JOIN — combine two tables), append queries (stack tables on top of each other), add calculated columns. Every step is recorded and reapplied automatically on refresh. This is the same Power Query from Chapter 39 — your Excel knowledge transfers directly.
STEP 03
Build the Data Model
In Model view, create relationships between tables by dragging fields. This is where Power BI's real power lies — you can have a fact table (transactions) related to multiple dimension tables (products, customers, dates, cost centres) and filter across all of them with one slicer. Build a proper Star Schema (one central fact table surrounded by dimension tables) — this is the foundation of a high-performance Power BI model. A good data model makes DAX formulas simple; a bad data model makes everything painful.
STEP 04
Write DAX Measures
DAX (Data Analysis Expressions) is Power BI's formula language for creating calculations. Create Measures (calculated values like Total Revenue, YoY Growth %, Budget Variance) and Calculated Columns (new columns in your table). DAX is context-aware — the same measure calculates correctly whether you're looking at total revenue, revenue by region, or revenue for a specific month — automatically. Key DAX functions: CALCULATE, SUM, SUMX, FILTER, ALL, RELATED, DIVIDE, IF, SWITCH, SAMEPERIODLASTYEAR. (Full detail in Section 40.6.)
STEP 05
Build Visuals on Report Pages
In Report view, drag measures and dimensions onto the canvas to create visuals. Add multiple visual types — bar charts, line charts, cards (KPI numbers), tables, matrices, maps, gauges. Arrange on a page like a dashboard. Add slicers for interactivity — when the user clicks a region in the slicer, all visuals on the page filter to that region simultaneously. Create multiple pages for different audiences (Executive Summary, Detailed P&L, Regional Analysis, YoY Comparison).
STEP 06
Publish & Share
Home → Publish → select a workspace in Power BI Service. The .pbix file uploads to the cloud. In Power BI Service: set up scheduled refresh (connect to cloud data sources and auto-refresh daily/hourly), share the report with colleagues (they view in browser), pin key visuals to a dashboard (the executive summary landing page), set up alerts (email notification when revenue drops below ₹X), configure row-level security (regional managers see only their region's data).
40.4
Power Query in Power BI — Connect & Transform Data

Power Query in Power BI is identical to Power Query in Excel (Chapter 39) — if you learned it there, it transfers 100%. Here we focus on finance-specific transformation patterns that come up constantly.

🔄
Unpivot — The #1 Finance Transformation
  • Financial data is often "wide" — months as column headers (Jan, Feb, Mar...) rather than "tall" (one row per month)
  • Power BI needs tall format — one row per record with a month column
  • Wide (bad for Power BI): Product | Jan | Feb | Mar | Apr...
  • Tall (good for Power BI): Product | Month | Revenue
  • Power Query fix: select all month columns → Transform → Unpivot Columns → instantly converts wide to tall
  • This single transformation unlocks time-based analysis (trend charts, YoY comparisons) that is impossible with wide format
  • Apply once → every future refresh automatically unpivots — no manual work
Most Important
🔗
Merge & Append Queries
  • Merge (like SQL JOIN): Combine two tables horizontally based on a matching key. Example: merge transactions table with product master table to bring in product category and cost — eliminates VLOOKUP in reports.
  • Join types: Left outer (all rows from first table, matching from second), Inner (only matching rows), Full outer (all rows from both). Left outer is most common in finance.
  • Append (like SQL UNION): Stack multiple tables vertically — same columns, different rows. Example: combine 12 monthly sales files into one table. Append all → one consolidated table automatically.
  • Append is how you consolidate multiple entity/branch files in management reporting — no more copy-pasting between Excel files
Data Combining
📅
Date Table — Essential for Time Intelligence
  • Every Power BI finance model needs a dedicated Date table — a table with one row per day covering all dates in your data
  • Columns: Date, Year, Quarter, Month, Month Name, Week, Day of Week, Financial Year, Financial Quarter, Is Weekday
  • Create in Power Query: = {Number.From(#date(2020,1,1))..Number.From(#date(2030,12,31))} — generates list of all dates
  • OR use DAX: CALENDARAUTO() — generates dates from min to max in your data model automatically
  • Mark as Date Table in Power BI → unlocks all time intelligence DAX functions (SAMEPERIODLASTYEAR, DATESYTD, DATEADD)
  • Without a proper Date table, YoY comparisons and YTD calculations are impossible or very complex
Time Intelligence
40.5
Data Modelling — Relationships & Star Schema
Foundation of Great Power BI

The data model is the most important part of a Power BI report. A good model makes everything easy. A poor model causes incorrect calculations, slow performance, and endless DAX complexity. The industry standard model design is the Star Schema.

⭐
Star Schema — The Gold Standard
  • Fact Table (centre of the star): Contains the measurable events — transactions, journal entries, sales orders. Has foreign keys to dimension tables. Large table (millions of rows). Contains numeric values to aggregate (revenue, quantity, cost).
  • Dimension Tables (points of the star): Contain descriptive attributes used for filtering and grouping. Small tables. Examples: Date dimension, Customer dimension, Product dimension, Cost Centre dimension, Account dimension.
  • Relationships: One-to-many from dimension to fact. Date table's Date → Fact table's Transaction Date. Customer table's Customer ID → Fact table's Customer ID.
  • When a user filters by "North Region" in the Customer dimension, Power BI automatically filters the fact table to only North Region transactions — and all measures recalculate accordingly.
Model Design
⚠️
Common Modelling Mistakes
  • Many-to-many relationships: Avoid where possible — causes ambiguous filter paths and incorrect calculations. Redesign the model to use a bridge table instead.
  • Too many tables joined in a chain: A → B → C → D (snowflake schema) — reduces performance. Flatten dimension tables where possible (star schema is faster).
  • Mixing fact and dimension data: Having product name, category, and revenue all in the same table — makes filtering complex. Separate into a Product dimension and Revenue fact.
  • No Date table: Using the transaction date column directly for time intelligence — will not work with DAX time intelligence functions. Always create a separate Date table.
  • Calculated columns instead of measures: Calculated columns are stored in memory for every row. Measures are calculated on-demand. Use measures for aggregations — calculated columns only for row-level attributes.
Avoid These
40.6
DAX — Data Analysis Expressions (The Power Language)
Most Important Skill in Power BI

DAX is the formula language of Power BI (and Power Pivot). It looks similar to Excel formulas but is fundamentally different — DAX is context-aware. A single DAX measure automatically calculates correctly at any level of aggregation (total, by region, by month, by product) without rewriting the formula.

Essential DAX Measures for Finance
Basic Aggregations
Total Revenue = SUM(Sales[Revenue])
Total Cost = SUM(Sales[Cost])
Gross Profit = [Total Revenue] - [Total Cost]
GP Margin % = DIVIDE([Gross Profit], [Total Revenue], 0)
Always use DIVIDE() instead of / to handle division by zero gracefully.
Year-over-Year Comparison
Revenue LY = CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(Dates[Date]))
YoY Growth = [Total Revenue] - [Revenue LY]
YoY Growth % = DIVIDE([YoY Growth], [Revenue LY], 0)
SAMEPERIODLASTYEAR is a time intelligence function — requires a proper Date table marked as Date Table.
Year-to-Date (YTD)
Revenue YTD = CALCULATE([Total Revenue], DATESYTD(Dates[Date]))
Revenue YTD LY = CALCULATE([Total Revenue], DATESYTD(SAMEPERIODLASTYEAR(Dates[Date])))
For financial year YTD (not calendar year): DATESYTD(Dates[Date], "31-03") — ends March 31 (India financial year).
Budget Variance
Budget = SUM(Budget[BudgetAmount])
Variance = [Total Revenue] - [Budget]
Variance % = DIVIDE([Variance], [Budget], 0)
Variance Flag = IF([Variance %] < -0.05, "⚠️ Below Budget", "✅ On Track")
CALCULATE — The Most Important DAX Function
CALCULATE(expression, filter1, filter2, ...)

Revenue North = CALCULATE([Total Revenue], Region[Region] = "North")
Revenue excl Returns = CALCULATE([Total Revenue], Sales[Type] <> "Return")
Revenue Last Month = CALCULATE([Total Revenue], PREVIOUSMONTH(Dates[Date]))

CALCULATE modifies the filter context — it's the engine behind 80% of all advanced DAX. Master this and you can build almost any measure.
ALL — Remove Filters
% of Total Revenue = DIVIDE([Total Revenue], CALCULATE([Total Revenue], ALL(Sales)))

ALL() removes ALL filters from a table — giving the grand total regardless of slicers. DIVIDE([Revenue], [Revenue with ALL]) gives % contribution of each row to the total. Essential for % share calculations.
RANKX — Ranking
Revenue Rank = RANKX(ALL(Products[Product]), [Total Revenue],,DESC)

Ranks each product by revenue across the entire product table (ALL removes filter). Use to show Top 10 products, rank sales reps by performance, rank cost centres by spend.
SWITCH — Multiple Conditions
Performance Rating = SWITCH(TRUE(),
  [Variance %] >= 0.1, "🟢 Excellent",
  [Variance %] >= 0, "🟡 On Target",
  [Variance %] >= -0.1, "🟠 Watch",
  "🔴 Critical")

Cleaner than nested IF statements. SWITCH(TRUE(),...) evaluates each condition in order and returns the first TRUE result.
Moving Average
3-Month Moving Avg Revenue =
CALCULATE([Total Revenue], DATESINPERIOD(Dates[Date], LASTDATE(Dates[Date]), -3, MONTH)) / 3

DATESINPERIOD defines a rolling window of 3 months ending at the current date. Dividing by 3 gives the average. Use for smoothing volatile monthly data in dashboards.
🔑 Filter Context vs Row Context — The Most Important DAX Concept
Filter Context: The set of filters currently applied to the data (from slicers, visual filters, report-level filters). CALCULATE is the tool to modify filter context.

Row Context: When iterating through rows (in SUMX, AVERAGEX, calculated columns), the current row being evaluated. DAX knows which row it's on and can access values from that row.

Example: Total Revenue = SUM(Sales[Revenue]) — this works in filter context. It sums all Revenue values for whatever filters are currently applied.

SUMX(Sales, Sales[Quantity] * Sales[Price]) — this iterates through each row (row context), multiplies Quantity × Price for that row, then sums all results. Use SUMX when you need row-level calculations before aggregating.

Understanding this distinction separates beginner DAX from expert DAX. Most "wrong numbers" bugs in Power BI come from confusion between these two contexts.

40.8
Building a Finance Dashboard — Step by Step
Practical Walkthrough

Let's build a complete CFO Dashboard — the most common Power BI deliverable in finance. This will consolidate everything covered so far into a real-world output.

PAGE 1
Executive Summary — The Landing Page
Top row: 4 Card visuals — Total Revenue (YTD), EBITDA Margin %, Cash Position, Revenue vs Budget %. These are the 4 numbers every CFO looks at first. Make them large, prominent, with conditional formatting (green if on track, red if below budget). Below: Line chart — Monthly Revenue (current year vs prior year). Bottom row: Clustered column chart — EBITDA by Business Unit. Map visual — Revenue by Geography (if relevant). This one page tells the entire financial story at a glance. Target: viewer understands company performance in 30 seconds.
PAGE 2
P&L Deep Dive
Matrix visual: Rows = P&L line items (Revenue, COGS, Gross Profit, Operating Expenses, EBITDA, Depreciation, EBIT, Interest, PAT). Columns = Months. Values = Actual, Budget, Variance, Variance %. Conditional formatting on Variance % — green positive, red negative. Slicers for Business Unit and Period (Q1/Q2/Q3/Q4). Waterfall chart: Budget vs Actual bridge — showing major drivers of variance. This replaces the monthly management accounts PDF — everything in one interactive view.
PAGE 3
Revenue Analytics
Top: Revenue by Product/Segment — stacked column with trend line. Middle: Revenue by Customer — top 10 customers by revenue (bar chart), customer concentration risk (% of revenue from top 5). Bottom: Revenue by Geography — map or bar chart. Add a slicer for time period. Add a drill-through — right-click on a customer bar → drill through to a customer detail page showing their transaction history, DSO, payment behaviour. This enables the CFO to go from summary to detail in two clicks.
PAGE 4
Cash Flow & Working Capital
Cards: Cash position, Receivable Days (DSO), Payable Days (DPO), Inventory Days, Cash Conversion Cycle. Line chart: 13-week cash forecast vs actual. Bar chart: Aged receivables by bucket (0-30, 31-60, 61-90, 90+ days). Gauge visual: DSO actual vs target. Table: Top overdue customers with amount, days overdue, and contact details. This is the treasury/working capital dashboard — refreshed daily from ERP data.
DESIGN
Dashboard Design Principles
Use a consistent colour theme (View → Themes — import company brand colours). Align all visuals to a grid. Use consistent font sizes (title 14px, axis labels 10px, card values 28px+). Add a header band with company logo, report title, and "Last refreshed: [date]". Put navigation buttons between pages (Insert → Buttons → Back/Forward). Apply report-level filters where needed. Test on different screen sizes. Final check: would a non-finance person understand the key message of each page within 30 seconds?
40.9
Filters, Slicers & Drill-Through
🎛️
Slicers — Interactive Filters
  • Slicers are visual filter controls on the report canvas — users click to filter all visuals on the page
  • Types: List slicer (checkboxes), Dropdown slicer (saves space), Between slicer (date range or number range), Tile slicer (buttons)
  • Sync slicers across pages: View → Sync Slicers — set the same slicer to filter multiple pages. User selects "North Region" on page 1 → stays filtered on page 2 and 3.
  • Date slicer: Use relative date filtering ("Last 30 days", "This quarter", "Last 3 months") — automatically updates as time passes
  • Best practice: Group slicers in a dedicated slicer panel on the left or top. Label them clearly. Limit to 3-5 slicers per page — too many overwhelms users.
User Interactivity
🔍
Drill-Through — From Summary to Detail
  • Right-click on a data point → Drill through → navigate to a detail page filtered to that context
  • Example: Right-click on "North Region" bar → drill through to Customer Detail page showing all North Region customers, their revenue, DSO, payment history
  • Setup: Create a detail page → drag the field you want to drill by (e.g. Region) into the "Drill through" field well → any visual with Region data now has drill-through to this page
  • Back button automatically added — user can return to summary page
  • Cross-report drill-through: Drill from one report to another report in the same workspace — powerful for enterprise reporting suites
Deep Dive
📊
Filters Pane vs Slicers — When to Use
  • Filters Pane (hidden from users): Apply permanent filters that users should not override — e.g. filter out test data, apply current year filter, remove blank rows. Hidden from end users.
  • Report-level filters: Apply to all pages in the report
  • Page-level filters: Apply to all visuals on one page
  • Visual-level filters: Apply to one specific visual only — e.g. show only Top 10 customers in a table
  • Slicers: Give to users for self-service filtering. Users can change these.
  • Rule: filters that users should control → slicers. Filters that define the report scope → filters pane.
Filter Strategy
40.10
Power BI Service — Share, Collaborate & Schedule
☁️
Publishing & Workspaces
  • Publish from Desktop: Home → Publish → select workspace
  • Workspaces: Collaborative environments in the cloud — team members with appropriate permissions can view, edit, or publish reports
  • My Workspace: personal space — not for sharing. Create separate workspaces for teams.
  • Finance workspace: all finance reports in one place — CFO Dashboard, Management Accounts, Treasury Report, Budget vs Actual
  • Roles: Admin (full control), Member (publish and edit), Contributor (publish but not delete), Viewer (read only)
  • Apps: Package a workspace as an App — distributes reports to a wider audience with a curated navigation experience
Publishing
🔄
Scheduled Data Refresh
  • In Power BI Service → Datasets → Schedule Refresh
  • Set refresh frequency: daily, multiple times per day (up to 8x/day for Pro, 48x/day for Premium)
  • Requires cloud-accessible data source OR an On-premises Data Gateway for local databases/files
  • On-premises Data Gateway: Install on a server/PC in your network — acts as bridge between Power BI cloud and your local database or Excel files. Allows automatic refresh from on-premises sources.
  • Refresh failure alerts: email notification if refresh fails — important for production dashboards
  • Finance impact: CFO dashboard refreshes at 7am every morning — leadership team always has overnight data when they arrive
Auto-Refresh
🔒
Row-Level Security (RLS)
  • Restrict what data each user sees based on their identity
  • Example: Regional managers see only their region's P&L. Country CFOs see all countries. Group CFO sees everything.
  • Setup in Desktop: Modelling → Manage Roles → create role with DAX filter (e.g. [Region] = USERPRINCIPALNAME() — matches region to user's email)
  • Assign users to roles in Power BI Service → Dataset → Security
  • Dynamic RLS: Create a mapping table (UserEmail | Region) and use USERPRINCIPALNAME() in DAX to dynamically filter based on logged-in user — one role for all users, data automatically filtered per person
  • Critical for enterprise finance dashboards — P&L data is sensitive
Data Security

🔑 The Professional Finance Workflow — Excel + Power BI Together
The best finance professionals use BOTH tools for different purposes — not one or the other.

Excel for: Financial modelling (DCF, budget models, scenario analysis), ad-hoc analysis, formulas-heavy calculations, working papers, anything that needs full formula transparency and flexibility.

Power BI for: Reporting and dashboards (management accounts, CFO dashboard, operational KPIs), large datasets, sharing with non-finance users, real-time data from operational systems.

Typical workflow: Build your financial model in Excel → Extract outputs (actuals, budget, forecasts) → Load into Power BI → Build dashboard → Share with leadership. Excel is the engine; Power BI is the display.

Key Takeaways, Common Mistakes & Action Steps

Part A — 10 Core Takeaways

1️⃣
Power BI Workflow
  • Connect → Transform (Power Query) → Model (relationships) → DAX (measures) → Visualise → Publish
  • Follow this sequence every time — skipping steps causes problems
2️⃣
Star Schema is Non-Negotiable
  • Fact table (transactions) at centre
  • Dimension tables (Date, Customer, Product) around it
  • One-to-many relationships: dimension → fact
  • Always create a separate Date table
3️⃣
CALCULATE is the Most Important DAX Function
  • Modifies filter context — enables any conditional calculation
  • Revenue LY, YTD, Budget Variance — all use CALCULATE
  • Master CALCULATE → master DAX
4️⃣
Unpivot is the Most Important Transformation
  • Financial data is often wide (months as columns)
  • Power BI needs tall (one row per record)
  • Power Query: select month columns → Unpivot
  • Enables all time intelligence features
5️⃣
Time Intelligence Requires Date Table
  • SAMEPERIODLASTYEAR, DATESYTD, DATEADD — all need a proper Date table
  • Mark as Date Table in Power BI
  • India financial year: DATESYTD(..., "31-03")
6️⃣
Use DIVIDE, Not /
  • DIVIDE([Revenue], [Budget], 0) handles division by zero gracefully
  • Revenue / Budget crashes with #DIV/0! equivalent when Budget = 0
  • Always use DIVIDE for ratio measures
7️⃣
Measures vs Calculated Columns
  • Measures: aggregations, calculated on demand, no memory storage — use for KPIs
  • Calculated columns: row-level, stored in memory — use for attributes and keys
  • Beginners overuse calculated columns — prefer measures
8️⃣
Excel + Power BI Together
  • Excel: financial modelling, complex formulas, ad-hoc analysis
  • Power BI: reporting, dashboards, sharing with non-finance
  • Not competitors — complementary tools in the modern finance stack
9️⃣
Row-Level Security for Finance
  • Finance data is sensitive — implement RLS for shared dashboards
  • Dynamic RLS with USERPRINCIPALNAME() — one role for all users
  • Test RLS thoroughly before publishing — wrong data access is a serious issue
🔟
Dashboard Design Principles
  • Executive summary page: 4-6 KPIs + trend chart — 30-second story
  • Consistent colours, fonts, alignment
  • Title = headline, not just description
  • Less is more — remove everything that doesn't add insight

Part B — Common Mistakes

❌ MISTAKE 1
Putting All Data in One Big Table (No Proper Model)
Beginners dump everything into one flat table — all dimensions and facts together. This causes performance issues, incorrect calculations, and makes DAX extremely complex. Always separate into a proper star schema: fact table + dimension tables with relationships. The data model is the foundation — get it right first.
❌ MISTAKE 2
No Date Table — Using Transaction Date Directly
Using Sales[Date] directly in visuals without a separate Date dimension table. Time intelligence functions (SAMEPERIODLASTYEAR, DATESYTD) will not work or will give wrong results. Always create a dedicated Date table with one row per day, mark it as Date Table, and build a relationship to your fact table.
❌ MISTAKE 3
Using Calculated Columns Instead of Measures for KPIs
Creating a calculated column "Revenue" instead of a measure. Calculated columns are stored for every row in the table — this bloats the model. KPI calculations should always be measures — they are calculated on demand using the current filter context and use no memory when not displayed.
❌ MISTAKE 4
Too Many Visuals on One Page — Information Overload
Finance professionals often want to show everything on one page. Result: 15+ visuals, tiny text, confusing layout — nobody can extract insight. Rule: maximum 6-8 visuals per page. One clear message per page. Use drill-through and drill-down to provide detail on demand rather than showing it all upfront.
❌ MISTAKE 5
Forgetting to Test Row-Level Security Before Publishing
Publishing a finance dashboard with RLS configured but not tested. Result: users see each other's data (RLS misconfigured) or see no data (RLS too restrictive). Always test RLS by using "View as Role" in Power BI Desktop before publishing. Then test again in Service by logging in as a test user with different permissions.

Part C — Key DAX Reference

Essential DAX Quick Reference
Total Revenue
= SUM(Sales[Revenue])
GP Margin %
= DIVIDE([Gross Profit], [Total Revenue], 0)
Revenue Last Year
= CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(Dates[Date]))
Revenue YTD
= CALCULATE([Total Revenue], DATESYTD(Dates[Date], "31-03"))
Budget Variance %
= DIVIDE([Total Revenue] - [Budget], [Budget], 0)
% of Total
= DIVIDE([Total Revenue], CALCULATE([Total Revenue], ALL(Sales)), 0)
Revenue Rank
= RANKX(ALL(Products[Product]), [Total Revenue],, DESC)
3M Moving Average
= CALCULATE([Total Revenue], DATESINPERIOD(Dates[Date], LASTDATE(Dates[Date]), -3, MONTH)) / 3
Revenue Filtered
= CALCULATE([Total Revenue], Region[Region] = "North")
Status Flag
= IF([Variance %] >= 0, "✅ On Track", "⚠️ Below Target")
